# V3.1 implementation contract

## Required modules
- Bullpen availability score: last 1/2/3 day workload, high-leverage usage, key arms available.
- Weather: temperature, wind speed/direction, precipitation and park/run adjustment.
- Injury/lineup: core-player availability and lineup-strength adjustment.
- Odds history: timestamped bookmaker/market/outcome/point/price snapshots.
- Settlement: final result and profit/loss in units.
- Backtest: chronological train/test split, calibration, ROI, hit rate, max drawdown and sample size.

## Decision policy
1. Never invent missing data.
2. Missing live odds => no EV claim.
3. Missing injury/weather => mark factor unavailable and reduce confidence.
4. `BET` requires positive EV and minimum data quality.
5. `LEAN` is informational and should not be treated as a full-strength wager.
6. `NO BET` is preferred over forcing a selection.

## Production sequence
1. Backend/API proxy.
2. PostgreSQL persistence.
3. Scheduled data ingestion.
4. Historical odds snapshots.
5. Settlement and ROI ledger.
6. Walk-forward backtesting.
7. Calibrated model weights.
8. Mobile UI consumes backend predictions.
